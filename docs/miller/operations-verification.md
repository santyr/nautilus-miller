This supports the fixture diagnosis, but the stalled worker stack was not captured: the original GDB attempt and four repeats all finished normally. After acquiring the context, all three modes passed5/5 each, plus the four-case conflict/entry run. No operation-manager code was changed. Original failures and normal GDB attempts are retained.

A proposed flat-view scope-reset diagnosis was rejected after observing exactly one managed shortcut controller in active Grid/List views; no corresponding production change was made. Conflict setup now creates the existing destination before opening its target and waits native Paste availability. Passive key/action/job observers confirm genuine Ctrl+V and the native `paste` action; the separate managed `paste_accel` is not falsely counted as the focused widget binding. Native tab controls wait slot loading independently of the deliberately paused transfer job, and choose the actual Replace button rather than assuming a default widget exists.
