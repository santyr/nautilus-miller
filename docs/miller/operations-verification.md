## Clipboard evidence boundary

The new `test/automated/display/test-miller-operations.c` reuses `test-utilities`, `MillerTestInput`, native FilesView/model APIs, NautilusClipboard, NautilusProgressInfoManager and the undo manager. Genuine compositor Ctrl+C/X/V/Z/Shift+Z supplies clipboard/undo input. Selection and initial directory disclosure are set through native APIs and are not claimed as pointer-navigation coverage. Empty-child Right/Left and delayed-transfer Ctrl+T are genuine input. Each test proves owned paths, exact Unicode-named payload bytes, source retention/removal, actual native job completion and native destination-model presence. Child/unrelated sibling sentinel contents are checked. Tests run unprivileged under the existing private bus/compositor and mounted disposable Home; host root/source are read-only.

The external clipboard source is another retained GTK process, not another widget sharing Nautilus's clipboard cache. Its real Ctrl+C offers GTK's public GdkFileList, serialized by GDK to text/uri-list. It minimizes its own window after that event so the original client regains Wayland keyboard focus. The delayed case stops only that retained owned provider after the offer, starts real Paste, proves no transfer job started yet, opens a new tab with genuine Ctrl+T, then resumes the provider. The captured original parent receives the exact contents; the newly active unrelated directory and disclosed child stay untouched, and active focus/action ownership stays in the new tab. This tests the existing captured destination and async clipboard path; it introduces no clipboard protocol or file-transfer implementation.
