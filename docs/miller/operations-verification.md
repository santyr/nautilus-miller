## Clipboard evidence boundary

The new `test/automated/display/test-miller-operations.c` reuses `test-utilities`, `MillerTestInput`, native FilesView/model APIs, NautilusClipboard, NautilusProgressInfoManager and the undo manager. Genuine compositor Ctrl+C/X/V/Z/Shift+Z supplies clipboard/undo input. Selection and initial directory disclosure are set through native APIs and are not claimed as pointer-navigation coverage. Empty-child Right/Left and delayed-transfer Ctrl+T are genuine input. Each test proves owned paths, exact Unicode-named payload bytes, source retention/removal, actual native job completion and native destination-model presence. Child/unrelated sibling sentinel contents are checked. Tests run unprivileged under the existing private bus/compositor and mounted disposable Home; host root/source are read-only.

The external clipboard source is another retained GTK process, not another widget sharing Nautilus's clipboard cache. Its real Ctrl+C offers GTK's public GdkFileList, serialized by GDK to text/uri-list. It minimizes its own window after that event so the original client regains Wayland keyboard focus. The delayed case stops only that retained owned provider after the offer, starts real Paste, proves no transfer job started yet, opens a new tab with genuine Ctrl+T, then resumes the provider. The captured original parent receives the exact contents; the newly active unrelated directory and disclosed child stay untouched, and active focus/action ownership stays in the new tab. This tests the existing captured destination and async clipboard path; it introduces no clipboard protocol or file-transfer implementation.

### Evidence boundaries and fixture corrections

Copy/Move To uses GtkFileDialog's existing in-process GTK backend, selected only for this test executable with public `GDK_DEBUG=no-portals`. Its ordinary folder chooser is not replaced or mocked. Selection/current-folder setup and intervening tab/branch changes use native APIs; opening the menu, activating its native item and accepting use genuine session input. Default portal-backed Copy/Move To remains separate acceptance; the native portal implementation smoke in the full Meson suite stays enabled. The toolbar-entry case uses real Ctrl+L then the native managed New Folder shortcut; the main browser's separate New Folder button is normally hidden, and the test does not force it visible.

The fixture now holds the default GMainContext on its main thread throughout g_test_run, matching a running application's context ownership while manually pumping GTK. Without that ownership, native conflict jobs intermittently stalled before showing a dialog across all modes. GLib documents that [invoke can run directly on a thread that acquires its context](https://docs.gtk.org/glib/method.MainContext.invoke.html); native Nautilus UI dispatch expects its application loop. This supports the fixture diagnosis, but the stalled worker stack was not captured: the original GDB attempt and four repeats all finished normally. After acquiring the context, all three modes passed5/5 each, plus the four-case conflict/entry run. No operation-manager code was changed. Original failures and normal GDB attempts are retained.

A proposed flat-view scope-reset diagnosis was rejected after observing exactly one managed shortcut controller in active Grid/List views; no corresponding production change was made. Conflict setup now creates the existing destination before opening its target and waits native Paste availability. Passive key/action/job observers confirm genuine Ctrl+V and the native `paste` action; the separate managed `paste_accel` is not falsely counted as the focused widget binding. Native tab controls wait slot loading independently of the deliberately paused transfer job, and choose the actual Replace button rather than assuming a default widget exists.

Logs above share `/tmp/nautilus-finder-`; detailed progression and preserved failed integrated runs include `operations-twenty-one-first`, `operations-twenty-two-first`, `operations-twenty-four-first`, `operations-conflict-observed-{first,second}`, `operations-conflict-context-red-backtrace[-0..3]`, `operations-tab-activation-first-green`, `operations-new-folder-focus-second-green`, and the 15 `operations-*-owned-context-repeat-*` logs. A failed integrated run remains failed even when earlier cases passed. Native chooser Network discovery also emitted the previously observed wsdd/cleanup diagnostics; these local namespaces do not isolate the host network. Tested private networking remains mandatory before Stage5 real remote fixtures.
